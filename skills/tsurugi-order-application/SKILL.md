# 案件探し・応募・最初の提案メッセージ

Tsurugi の応募で発注者に届くのは**受注者プロフィールだけ**。提案の中身は、応募すると自動で開く案件メッセージで伝える。

## MCP で使えるか確かめる

案件検索や応募のツールが無いときは、MCP からは操作できない。Web の「案件を探す」（`https://tsurugi.marketing/marketplace/provider/orders`）を案内し、案件との相性の整理と提案文作りを手伝う。

## 1. 探す

- `list_industry_types`・`list_support_types` で選択肢を取り、`search_published_orders` で条件検索する（キーワード・都道府県・業界・支援領域・対応形式）。
- 候補ごとに、月額予算・応募期限・対応形式・応募数を一覧で見せる。
- 気になる案件は `get_published_order` で詳細（案件の説明・お願いしたい業務・求めるパートナー・支援期間など）を読む。

## 2. 合うか整理する

- 案件の課題・求めるパートナーと、自分の受注者プロフィール・実績を突き合わせ、「合う点／足りない点／確認したい点」を短くまとめる。
- 関連する自分の実績を探す（`list_own_track_records`）。

## 3. 応募の前に

- `get_order_application_status` で、応募済みか、受注者プロフィールがあるか、受注要件を満たしているかを確かめる。満たしていなければ `tsurugi-provider-profile` で整える。
- 次のことを伝える。
  - **応募は 1 案件につき 1 回だけ。辞退したあとも同じ案件には再応募できない。**
  - 応募すると、いまの受注者プロフィールがそのまま発注者に届く。
  - 自分の案件には応募できない。
- ユーザーが明示的に「応募して」と言ったときだけ `apply_to_order` を呼ぶ。

## 4. 最初のメッセージ（提案）を書く

応募したら `list_order_conversations`（受注者側）で会話を見つけ、提案文を下書きする。

- プレーンテキスト、2000 文字以内、添付はできない（資料は実績ページなどの URL で示す）。
- 構成の目安:
  1. あいさつと応募した理由（1〜2 文）
  2. 理解した課題と、目指す状態（案件の説明を自分の言葉で）
  3. 進め方の案（最初の 1〜2 か月で何をするか）
  4. 根拠になる実績（公開ページの URL はユーザーに確認する）
  5. 体制と役割、稼働の目安、支援期間
  6. 費用感（言える範囲で、案件の予算と照らして）
  7. 確認したい点（2〜3 個）
- 聞いていない実績や数値は書かない。成果を保証する表現は避ける。
- 文面を見せて承認を得てから `send_order_message` で送る。送ると取り消せない。

## 応募したあと

- 状況は `list_own_order_applications` で確認する（応募中／承諾済み／却下済み／辞退済み）。発注者が応募を承諾すると「マッチング成立」。契約・支払いは当事者どうしで決める（Tsurugi はマッチング成立までを支援する）。
- 辞退は `withdraw_order_application`。取り消せず、再応募もできないので必ず確認してから。
- メッセージの確認と返信は `tsurugi-messages`。通知は届かないので、こまめに確認する。
