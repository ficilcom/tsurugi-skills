# 案件の作成と公開（発注者向け）

案件は、受注者が「自分に合うか」「何を提案すればよいか」を判断する材料。背景と課題、実現したい状態、お願いしたい範囲が具体的なほど、合う受注者から応募が集まる。

## MCP で使えるか確かめる

`create_order` などのツールが無いときは、MCP からは保存できない。Web の案件作成画面（`https://tsurugi.marketing/marketplace/requester/orders/new`）で入力してもらい、文章作りだけを手伝う。

## 1. 聞き取る

1 問ずつ聞く。予算・期間など未定の項目は空欄のまま公開できるので、無理に決めなくてよい。

- 背景・現在の課題・実現したい状態
- お願いしたい業務（例: 現状の分析、施策の企画、運用代行、レポート作成）
- 求めるパートナー（経験・スキル・進め方）
- 業界・商材と支援領域（それぞれ 1 つ。`list_industry_types`・`list_support_types` の一覧から選び、ID を推測で作らない）
- 対応形式: オンライン／現地／オンライン＋現地。現地を含むときは都道府県と市区町村
- 予算（月額、または全体の概算）、支援期間、応募期限
- 公開範囲の希望（下の「公開範囲」）

## 2. 書く

- **案件タイトル**: 何の支援を求めているかが一目でわかるように（例: 「BtoB SaaS のリスティング広告の運用改善支援」）。
- **案件の説明**: 「背景」「現在の課題」「実現したい状態」の順に書く。検索はタイトルと説明が対象なので、業界や施策の言葉を自然に入れる。
- **お願いしたい業務**: 1 行に 1 項目で書く（Web では箇条書きで表示される）。
- **求めるパートナー**: 必須の経験と、あれば嬉しい経験を分ける。進め方（定例の頻度、使うツール、稼働の目安）も書く。
- 予算と応募期限は、決まっていれば入れる。予算順・期限順の並べ替えでは、未入力の案件が後ろに回る。
- 実際と違う条件や誤解を招く表現は書かない。利用規約で、発注者・業務内容・条件・報酬を正確に示すことが求められている。
- 社外秘や個人情報は書かない。公開範囲によっては、ログインしていない人も読める。

## 3. 下書き保存する

- 案を見せて確認を取り、`create_order` で下書きを作る。
- 単位に注意する。月額予算は**円**、概算予算は**万円**で入力する（取得すると概算予算も円で返る）。日付はタイムゾーン付きの日時（例: `2026-11-01T00:00:00+09:00`）。
- オンラインの案件には都道府県と市区町村を入れない。
- 直すときは `get_own_order` で現在の値を取り、`edit_order` に全項目を渡す。編集できるのは下書きのときだけ。
- 発注者の立場や支払条件などの任意項目は、ツール定義を見て、ユーザーが決めているものだけ入れる。

## 4. 公開する

- `get_own_order` の `isPublishable` で公開できるか確かめる。公開に必要なのは、案件タイトル・案件の説明・業界・商材・支援領域・対応形式（現地を含むときは都道府県と市区町村も）。
- 公開した案件の内容は MCP からは編集できない。公開前に内容を確定させる。
- ユーザーが明示的に頼んだときだけ `publish_order` を呼ぶ。公開すると、公開範囲に応じて受注者が検索・応募できるようになる。

## 公開範囲

MCP で作成・編集した案件は「会員限定公開」になる。変えたいときは、内容を確定して公開したあとに、Web の案件編集画面（`https://tsurugi.marketing/marketplace/requester/orders/{id}/edit`）で変えてもらう。下書きのうちに Web で変えても、そのあと `edit_order` を使うと会員限定公開に戻る。

| 公開範囲 | 見られる人 |
|---|---|
| 一般公開 | 誰でも（ログインしていない人も）検索・閲覧できる |
| 会員限定公開 | ログインしている人だけが検索・閲覧できる |
| 非公開 | 検索には出ない。URL を知っているログインユーザーだけが閲覧できる |

## 募集の終了と再公開

- `close_order`: 募集を終了する。応募中の応募はそのまま残る。
- `republish_order`: 応募を承諾していなければ、募集終了の案件を再公開できる。
- どちらもユーザーの明示的な指示があってから呼ぶ。
- 自分の案件の一覧は `list_own_orders`。応募が届いたら `tsurugi-applicant-selection` で確認・比較する。
