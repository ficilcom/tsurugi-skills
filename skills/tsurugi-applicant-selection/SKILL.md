# 応募者の確認・比較・承諾（発注者向け）

Tsurugi の応募で届くのは、応募者の受注者プロフィールと、そのあとの案件メッセージだけ。応募の時点では提案文が無いので、プロフィール・実績・メッセージを根拠に比べ、足りない点はメッセージで確かめる。

## MCP で使えるか確かめる

`list_order_applications` などのツールが無いときは、MCP からは操作できない。Web の案件管理画面（`https://tsurugi.marketing/marketplace/requester/orders`）を案内し、比較の整理と質問文作りを手伝う。

## 1. 応募を一覧する

- `list_own_orders` で案件ごとの応募数と未対応の応募数を見せ、対象の案件を選んでもらう。
- `list_order_applications` で応募者（名前、個人／企業、状態、応募日時）を一覧する。

## 2. 材料を集める

- メッセージ: 応募ごとの会話を `get_order_conversation` で読む。読むだけでは既読にならない。
- プロフィールと実績: MCP からは応募者のプロフィールを読めない。Web の応募一覧（`https://tsurugi.marketing/marketplace/requester/orders/{orderId}/applications`）の「プロフィール・実績を確認」から見てもらい、内容を貼ってもらうか要点を聞く。

## 3. 比べる

次の観点で、応募者ごとに表にまとめる。

- 案件の課題をどう理解しているか
- 進め方の案
- 根拠になる実績（期間・条件・担当範囲がはっきりしているか）
- 体制と役割、稼働の目安、期間
- 費用感と予算との差
- 不明な点・気になる点

本人の申告と、実績などで確かめられたことを分けて書く。わからない項目は推測で埋めず、空けておく。決めるのはユーザーで、このスキルは判断の材料を整理する。

## 4. 確認の質問を送る

- 不明な点について、応募者ごとに質問文を作る（体制・役割・進め方・稼働・費用感など）。
- プレーンテキストで 2000 文字以内。文面を見せて承認を得てから `send_order_message` で送る。送ると取り消せない。
- 通知は届かないので、相手の返信は `tsurugi-messages` で確かめる。

## 5. 決める

- **承諾**（`accept_order_application`）: 選んだ応募が「承諾済み」になり、**案件は募集終了になって、ほかの応募中の応募はすべて「却下済み」になる**。元に戻せず、その案件は再公開できなくなる。この影響を伝え、ユーザーの明示的な指示があってから呼ぶ。
- **却下**（`reject_order_application`）: 1 件ずつ却下する。案件の募集は続く。元に戻せないので、明示的な指示があってから呼ぶ。
- 承諾も却下も、相手に通知は届かない。選ばなかった応募者には、お礼と結果をメッセージで伝えるよう提案する（応募の状態に関係なくメッセージは送れる）。
- 誰も選ばないときは、`close_order` で募集を終了できる（`tsurugi-order-posting`）。

## 承諾したあと

- 応募を承諾すると「マッチング成立」になる。進め方・契約・支払いは当事者どうしでメッセージで相談して決める（Tsurugi はマッチング成立までを支援する）。
- 表記は「応募を承諾」「マッチング成立」を使い、「採用」「成約」は使わない。
