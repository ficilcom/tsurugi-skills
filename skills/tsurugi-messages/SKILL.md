# 案件メッセージの確認と返信

Tsurugi には、応募やメッセージを知らせるメール・プッシュ通知が無い。このスキルで定期的に確かめる。

## MCP で使えるか確かめる

メッセージのツールが無いときは、MCP からは操作できない。Web の「メッセージ」を案内する。

- 応募した側: `https://tsurugi.marketing/marketplace/provider/messages`
- 案件を出した側: `https://tsurugi.marketing/marketplace/requester/messages`

## 進め方

1. **未読数を見る。** `get_order_conversation_unread_count` を、自分が応募した側（`applicant`）と案件を出した側（`requester`）の両方で呼ぶ。
2. **会話を一覧する。** `list_order_conversations` で未読のある会話を新しい順に出す（案件名・相手・最後のメッセージ・応募の状態）。続きは返ってきたカーソルで取る。
3. **読んで要約する。** `get_order_conversation` で読み、会話ごとに「相手の要望・質問」「こちらがやること」「期限」をまとめる。読むだけでは既読にならない。
4. **返信案を作る。** 質問には漏れなく答える。決まっていないことは決まっていないと書く。次の一手（日程・資料・確認事項）をはっきりさせる。プレーンテキストで 2000 文字以内、添付はできない。
5. **送る。** 文面を見せて承認を得てから `send_order_message` を呼ぶ。送ると取り消せない。
6. **既読にする。** ユーザーが望めば `mark_order_conversation_read` を呼ぶ。

## 注意

- 会話は当事者 2 者だけが見られる。それでも第三者の個人情報や社外秘は書かない。
- 応募の承諾・却下はこのスキルでは行わない。承諾すると募集が終わり、他の応募はすべて却下されるため、Web の応募一覧から操作してもらう。
- 契約・支払いの条件は当事者どうしで合意する。Tsurugi はマッチング成立までを支援する。
- 表記は「応募を承諾」「マッチング成立」を使い、「採用」「成約」は使わない。
