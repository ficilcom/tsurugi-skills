# 受注者プロフィールの整備

受注者プロフィールは、案件に応募したときに発注者が見る自己紹介。応募にはメッセージ欄が無いので、**このプロフィールが応募の中身になる**。保存するとすぐに一般公開される（下書きは無い）。

## MCP で使えるか確かめる

`get_own_service_provider_profile` などのツールが無いときは、MCP からは保存できない。Web の `https://tsurugi.marketing/marketplace/provider/profile/edit` で入力してもらい、文章作りだけを手伝う。

## 受注要件（6 つすべて満たすと応募できる）

1. ひとこと紹介: 1 文字以上
2. 自己紹介: 100 文字以上（前後の空白を除く）
3. 対応できる業務範囲: 100 文字以上（前後の空白を除く）
4. 得意な業界・商材: 1 つ以上
5. 支援領域: 1 つ以上
6. 現地対応可能エリア: 1 つ以上。**オンラインだけで受ける人も 1 つ以上必要**

## 進め方

1. `get_own_service_provider_profile` で現状を取得し、受注要件の不足を示す（無ければ新規作成）。
2. 聞き取る: 得意な支援（何を、どの業界で）、代表的な実績、進め方と体制（個人かチームか、稼働の目安）、対応しない範囲、オンライン対応の可否、現地対応できる都道府県。
3. 業界・商材と支援領域は `list_industry_types`・`list_support_types` の一覧から選ぶ。ID を推測で作らない。
4. 文章の案を作り（下のコツ）、ユーザーに見せて直す。
5. 承認を得てから保存する。無ければ `create_service_provider_profile`、あれば `update_service_provider_profile`。更新は全項目の置き換えなので、変えない項目も現在の値を渡す。**保存するとすぐ公開される。**
6. 保存後にもう一度取得し、受注要件を満たしたか確かめる。

表示名とプロフィール画像は MCP からは変えられない（Web の個人アカウント設定で変える）。

## 書き方のコツ

- **ひとこと紹介**: 強みを一言で（例: 「BtoB SaaS の広告運用と計測設計が得意」）。実績ページの著者紹介に表示される。
- **自己紹介**: 誰の、どんな課題を、どう解決してきたか。検索の対象で、検索結果の説明文にもなるので、冒頭に要点を置く。
- **対応できる業務範囲**: 作業の単位で具体的に（戦略立案、運用代行、レポート作成、制作ディレクションなど）。対応しない範囲も書くと発注者が判断しやすい。これも検索の対象。
- 実績（`tsurugi-track-record`）と内容をそろえる。根拠になる実績があると判断されやすい。
- **書かないもの**: 電話番号、メールアドレス、詳しい住所。連絡は応募後の案件メッセージで行う。
- 誇張、成果の保証、根拠のない順位は書かない。
