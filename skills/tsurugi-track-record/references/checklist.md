# 実績のチェックリスト

## 中身

- [ ] 背景・課題: 業界・事業の状況と、解くべき問題がわかる
- [ ] 役割: 自分（自社）が担当した範囲がわかる。チームの成果と自分の貢献を混ぜていない
- [ ] 施策: 何を・なぜ・どう進めたかがわかる。ツール名の羅列で終わっていない
- [ ] 成果: 数値には期間・条件・比較対象が付いている（例: 「施策前の 3 か月平均と比べて」）。言い切れないことは事実に合わせた表現にしている
- [ ] 学び: 読み手が自分の課題に当てはめられるポイントがある
- [ ] 画像がなくても文章だけで伝わる

## 公開してよいか

Tsurugi の利用規約では、公開する内容に個人情報・秘密情報・顧客情報・第三者の権利を含めないこと、虚偽や誤解を招く表示をしないことが求められている。

- [ ] 顧客名・商材名・未公開の数値を出す許可がある。無ければ「国内の BtoB SaaS 企業」のように置き換えている
- [ ] 個人情報・社外秘・第三者の権利を含まない
- [ ] 成果の保証や根拠のない順位など、誇張や誤解を招く表現がない

## 見つけてもらう

- [ ] タイトルに支援領域・業界・成果の要点が入っている（実績の検索はタイトルだけが対象）
- [ ] 本文の冒頭 120 文字ほどで要点が伝わる（検索結果や共有時の説明文になる）
- [ ] 見出しを使っている（目次になる）
- [ ] タグが内容に合っている（タグでも検索される）
