# 実績ポートフォリオの作成・改善

Tsurugi の実績は自己紹介ではなく、**発注者がパートナーを選ぶときの根拠**。量より、読み手が「何をして、どうなったか」を確かめて納得できることを優先する。

## 新しく作る

1. **聞き取る。** 1 問ずつ聞き、答えにくい所は飛ばしてよい。
   - 背景・課題: どんな事業・状況で、何が問題だったか
   - 役割と担当範囲: チームの中で自分が何をしたか
   - 施策: 何を、なぜ、どの順でやったか
   - 成果: 数値なら期間・条件・比較対象も。定性的な変化でもよい
   - 学び: 他の案件にも使えるポイント
   - 公開してよい範囲: 顧客名・商材名・数値を出してよいか
2. **書く。** 構成は「## 背景・課題」「## 施策」「## 成果」、必要なら「## 学び」。[references/checklist.md](references/checklist.md) を満たす。
   - **聞いていない事実・数値・社名は書かない。** 足りなければ質問するか、伏せた表現にする。
   - 成果を保証する表現や、根拠のない「No.1」などは使わない。
3. **タイトルを付ける。** 実績の検索はタイトルだけが対象なので、支援領域・業界・成果の要点を入れて具体的に（255 文字以内）。
   - 例: 「BtoB SaaS のリスティング広告で、半年かけて獲得単価を下げた運用設計」
4. **見せて確認する。** タイトル・本文・タグの案を見せ、直しを反映する。
5. **下書き保存する。** `create_draft_track_record` で下書きを作り、`update_track_record` で保存する。本文の形式は [references/body-format.md](references/body-format.md)。
6. **Web で仕上げてもらう。** カバー画像や本文の画像は MCP からアップロードできない。編集画面 `https://tsurugi.marketing/track-records/{id}/edit` を案内する。
7. **公開する。** ユーザーが明示的に頼んだときだけ `publish_track_record` を呼ぶ。公開すると、ログインしていない人や検索エンジンも含めて誰でも読める。

## 既存の実績を直す

1. `list_own_track_records` で一覧を出し、対象を選んでもらう。
2. `get_own_track_record` で取得し、checklist.md に沿って講評する（良い点・足りない情報・直し方）。
3. 足りない情報を聞き取り、書き換え案を見せる。
4. 承認されたら `update_track_record` で保存する。全項目の置き換えなので、画像 URL・タグ・変えない部分は取得した値をそのまま渡す。公開中の実績はすぐに反映される。

## タグ

- `list_tags` があれば既存のタグから選び、無いものだけ `create_tag` で作る（例: 広告運用、SEO、CRM、SNS広告）。
- タグを一覧するツールが無いときは、新規作成では `tagIds` を空にし、Web の編集画面でタグを付けてもらう。既存の実績を更新するときは、取得したタグの ID を引き継ぐ。

## 確認してから実行する操作

- 公開（`publish_track_record`）と、非公開に戻す（`unpublish_track_record`）
- 削除（`delete_track_record`）は元に戻せない。必ず明示的な指示を受けてから。
